# ログの仕組み 設計書

2026-11-07 作成(実装済みの `common/log.js` から起こしたもの)。同日、自動の操作ログを `common/autolog.js` に分け、値の変更・選択のログをやめた。2026-11-08、起動のログ(`log.started`)を足し、`autolog.js` を `log.js` に戻して1ファイルにした(下の「1ファイルに戻した理由」)

## 概要

全ページ(45ツール・3ランチャー・一覧)の操作と結果を、同じ形の日本語の文でブラウザのコンソールに残す仕組みです。スマホで不具合が起きた時に、デバッグ画面(eruda)を開けば「何を押して、何が起きたか」が順に読めることを目的にしています。サーバーには何も送りません。

- 実装: `common/log.js` の1ファイル(前半がログの本体、後半が押下の自動ログ)。全ページが `site.js` より先に読み込む。
- 書き方の決まり(ページを書く人向け): [../logging.md](../logging.md)

## 課題と方針

| 課題 | 方針 |
| --- | --- |
| ツールごとに押下ログを手書きすると、書き忘れや文言の揺れが出る | ボタン・リンクの押下ログはページ全体で1か所から自動で書く。ページ側は部品に名前を付けるだけ |
| ログの本体と自動の操作ログが1ファイルに混ざり、片方を直す時にもう片方も読む必要がある | ファイルの中で前半(本体)と後半(押下の自動ログ)に分け、後半は `log()` を呼ぶだけで本体の中には触れない。文言もそれぞれの前に置く(2026-11-07 に2ファイルに分けたが、11-08 に1ファイルに戻した) |
| 値の変更や選択(「〜を「…」にしました」「〜を選択しました」)のログが多く、読みにくい | 自動では出さない(利用者の判断)。必要な時だけページ側で結果として書く |
| ログの仕組みが site.js と tool-kit.js に分かれ、ランチャーは自動ログの外だった | `log.js` に集め、全ページで読む |
| 文言がコードの中に散らばり、どんなメッセージがあるか分からない | 文言は先頭の `MSG` に埋め字付きで並べ、`format()` で埋める |
| eruda は開いた後のログしか拾わない | 直近500行を手元に残し、開いた時にまとめて出し直す |
| 個人情報(入力文字・ファイル名・位置)がログに残る | 文字入力は自動ログの対象外。一覧の行は番号で名前を付ける |
| 押下と結果の順番が前後すると読みにくい | 自動ログはキャプチャで動かし、ページ側の処理より先に出す |
| `log.js` が読めないとページが止まる | `site.js` は何もしないログで代わりに動く。各ページの HTML の読み込み確認が案内を出す([page-base.md](./page-base.md)) |

### 1ファイルに戻した理由(2026-11-08)

- どのページも必ず両方を続けて読んでいて、片方だけを使うページが無い。2つに分けても、HTML の読み込みが1本増えるだけだった(利用者の判断)。
- 分けた目的(片方を直す時にもう片方を読まない)は、ファイルの中で前半・後半に分け、見出しの注釈を付けることで保つ。

## 仕様

### 公開するもの(window.log)

| 名前 | 動き |
| --- | --- |
| `log(msg)` / `log.info(msg)` | info で出す |
| `log.warn(msg, err?)` | warn で出す。err があれば ` [詳細] …` を付ける |
| `log.error(msg, err?)` | error で出す。Error はコンソールの2つ目の引数にも渡す(スタックを開ける) |
| `log.debug(msg)` | debug で出す(細かい内部の状態だけ) |
| `log.step(name, fn, detail?)` | fn を実行して所要時間を測り、成功・失敗を1行で出す。`{ok, value}` か `{ok, error}` を返す |
| `log.started(detail?)` | 起動のログを1回だけ出す。時間(ページを開き始めてから)は自動で付ける。2回目からは何もしない |
| `log.started.later()` | 「起動のログは後でページが出す」と宣言する(自動で出さない) |
| `log.MSG` | `log.js` の前半の文言の一覧(変更不可。押下の文言は後半の `MSG`) |
| `log.format(text, vals)` | 文言の `{キー}` を値で埋める。値の無いキーは空にする |
| `window.__logReplay()` | 履歴をまとめて出し直す(site.js のデバッグボタンが呼ぶ) |

### 1行の形

`2026-11-07 05:00:12.345 「開始」ボタンを押下しました`

時刻はローカル時刻で、年から始まりミリ秒まで(`stamp()`)。Date の標準の書式にはこの形が無いため、数字を桁そろえしてつなぐ。

### メッセージの一覧

`log.js` の後半(押下の自動ログ)の MSG:

| キー | 文言 |
| --- | --- |
| pressButton | `{グループ}「{名前}」ボタンを押下しました` |
| pressLink | `{グループ}「{名前}」のリンクを押下しました` |
| press | `{グループ}「{名前}」を押下しました` |
| group | `「{グループ名}」の`(`{グループ}` に入る前置き) |

`log.js` の前半の MSG:

| キー | 文言 |
| --- | --- |
| stepDone | `{名前}が終わりました({時間}ms)` |
| stepDoneWith | `{名前}が終わりました({詳細} / {時間}ms)` |
| stepError | `{名前}でエラーが発生しました` |
| started | `起動しました({時間}ms)` |
| startedWith | `起動しました({詳細} / {時間}ms)` |
| uncaught | `予期しないエラーが発生しました` |
| unhandled | `未処理の非同期エラーが発生しました` |
| detail | ` [詳細] {詳細}` |
| replay | `--- ここまでの履歴 ---` |

### 自動ログの対象

| 部品 | 契機 | 文言 |
| --- | --- | --- |
| button・`[role=button]` | click(人が押した時だけ) | pressButton |
| `a[href]` | click | pressLink |
| `data-log` を付けた要素 | click | press |
対象外: 入力部品の値の変更と選択(select・チェック・ラジオ・スライダー・色・ファイル・文字入力)、`<label>` の押下、名前の無い部品、`data-log="off"` の中、無効なボタン、プログラムから呼んだ `click()`。

### 名前の決め方

1. `data-log`
2. `aria-label`
3. `title`
4. 部品の文字

空白をまとめ、先頭の飾り(●■▶⏸⏹⏺)は文字が残る時だけ外し、24文字で切る。親に `data-log-group` があれば `「…」の` を前に付ける。

### 起動のログ(2026-11-08 追加)

各ページが手で書いていた `起動しました(…)` を、共通の `log.started()` にそろえた。それまでは52か所で書き方が違い(中身の無い物、かっこの前の空白、時間の有無)、書き忘れたページは何も出なかった。

| ページの書き方 | 出る行 |
| --- | --- |
| 何も書かない | 読み込みが終わった時に自動で `起動しました(180ms)` |
| 初期化の最後に `log.started('音色 ピアノ')` | `起動しました(音色 ピアノ / 180ms)` |
| 最初に `log.started.later()`、準備ができた時に `log.started('ツール 47冊')` | 準備ができた時に `起動しました(ツール 47冊 / 820ms)` |

- 時間は `performance.now()`(ページを開き始めてから。通信の時間も入る)。「開いてから使えるまで」が分かるようにするため。
- 自動で出すのは `load` の後(`setTimeout 0`)。ページの初期化と、`load` を待つページの処理が先に済むようにするため。
- 1回だけにするのは、2か所に書いても同じ行が重ならないため。
- `later()` は、一覧の読み込みや保存したデータの読み出しを待ってから準備が終わるページ(ランチャー、音楽プレーヤーなど)で使う。宣言したのに呼ばなかった時は、何も出ない(どこかで止まった合図になる)。

## 処理の流れ

1. `log.js` を読み込むと、`window.log` を作り、`error` / `unhandledrejection` の見張りを始める。続いて後半が `click` の見張り(キャプチャ)を始める。
2. ページの処理が `log()` などを呼ぶと、時刻を付けてコンソールに出し、履歴(500行まで、古い物から捨てる)に積む。
3. 人が部品を操作すると、ページの処理より先に自動ログが名前を決めて1行出す。続いてページの処理が結果を書く。
4. デバッグボタンを押すと、`site.js` が eruda を読み込み、`__logReplay()` で履歴を出し直す。以後は履歴に積まずコンソールへ直接出す(eruda が拾う)。

## 制限事項

- 履歴は500行まで。それより古い物はデバッグ画面を開いても見えない。
- ページを閉じるとログは消える(保存も送信もしない)。
- 値の変更・選択、キーボード操作、ドラッグ、3D 空間のタップなどは自動で出ない。要る時はページ側で結果として書く。
- `stamp()` は端末の時計とタイムゾーンに従う。

## 確認

- ブラウザ(Playwright)で、各部品の自動ログが1回の操作で1行だけ出ること、`log.step` の成功と失敗、警告、予期しないエラー、未処理の非同期エラーの文言とレベルを確かめた。
- ポモドーロタイマー、画像分類、画像ビューア、画像変換、一覧ページ、デスクトップ風ランチャーで動かした。
- 3D ランチャー2つは three.js が開発環境で読めないため、構文チェックのみ。(2026-11-07 から開発環境で動かせる。`docs/lessons.md`)
- 起動のログ: `tests/core/log.test.js` で形・1回だけ・自動・`later()` を試す。`tests/smoke.js` で全ページが `起動しました` をちょうど1回出すことを確かめる(2026-11-08)。
