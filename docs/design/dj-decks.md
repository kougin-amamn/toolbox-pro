# DJデッキ(DJ Decks) 設計書

状態: 実装済み(実機は要確認)。作成 2026-11-08、更新 2026-11-08。

## 1. 概要

2台のレコードとミキサーで、手元の曲をつないで遊ぶ、分かりやすい DJ のツールです。利用者が渡した参考の画面(VINYL LAB Dual Deck)の並び・ボタン・色・エフェクトを取り入れます。

- 位置づけ:
  - `dj-turntable`(通常版): 1台。いちばん軽い。smartools に残っている。
  - `dj-decks`(このツール): 2台とミキサー。文字のボタンとスライダーで、迷わず使える。スクラッチの音は Pro と同じ。
  - DJターンテーブル Pro: 2台とミキサー。実機に似せた見た目、BPM、細かいミキサー。このリポジトリにある。
- うまくいったと言える目安: 初めて開いた人が、説明を読まずに2曲を読み込み、クロスフェーダーでつなげる。
- 前提: https(AudioWorklet に必要)。AudioWorklet がある、今のスマホとパソコンのブラウザ。外部のライブラリは使わない。
- やらないこと:
  - BPM の自動検出と、テンポを揃える機能(SYNC)。DJターンテーブル Pro に任せる。
  - 曲の保存(次に開いた時に残すこと)。

## 2. 基本設計

### 2.1 要件と課題

要件:

| 番号 | 要件(受け入れの条件) |
| --- | --- |
| R-01 | LOAD TRACK で曲を選んだ時、そのデッキに読み込み、曲名と長さを出し、曲から作った波形を出す |
| R-02 | PLAY を押した時、盤の回転が立ち上がって(約 0.7 秒)鳴る。もう一度押すと、回転がゆっくり落ちて(約 0.6 秒)止まる |
| R-03 | CUE を押した時、止めて曲の頭に戻す。RESET を押した時、再生を続けたまま曲の頭に戻す |
| R-04 | LOOP が ON の時、曲の終わりで頭に戻って続ける |
| R-05 | HOT CUE を初めて押した時、今の位置を覚える。次からは、その位置へ飛ぶ |
| R-06 | PITCH を動かした時、−16%〜+16% で速さと音の高さが変わる(レコードと同じく、速くすると高くなる) |
| R-07 | 盤を指でなぞった時、なぞった速さと向きで音がこすれて鳴る(逆回しも)。止めると音も止まる。離すと、回っていた盤はそのまま回り続ける(スリップマットと同じ) |
| R-08 | 波形とシークバーで、今の位置が分かる。シークバーを動かした時、その位置へ飛ぶ |
| R-09 | ミキサー: MASTER、CH A / CH B の音量、HI / MID / LOW(−24〜+12dB)、CROSSFADER が、すぐ音に効く |
| R-10 | FILTER・ECHO を押した時、両方のデッキの音に効く(ON / OFF) |
| R-11 | STOP ALL で両方を止める。RESET MIXER でミキサーを最初の値に戻す |
| R-12 | 音の処理が無いブラウザ・読めない曲の時、画面に理由を出す |

課題と方針:

| 課題 | 方針 |
| --- | --- |
| 参考は、波形が曲と関係の無い飾り | 読み込んだ曲を解析して、本物の波形を描く(決定 2026-11-08) |
| 参考の FILTER と ECHO が、デッキ A にしか効かない | 2台を混ぜた後(マスターの前)に入れ、両方に効かせる |
| 参考の AUDIO START は、押さないと音が出ない | 最初の PLAY で音の処理を始めるので、ボタンは置かない。並びは、STOP ALL と RESET MIXER を残す |
| 参考の PITCH は、ブラウザが音の高さを保つ(レコードらしくない) | 速さと一緒に音の高さも変える(`preservesPitch = false`) |
| 参考はファイル名をそのまま扱う | 画面には出すが、ログには出さない(サイトの決まり) |
| 曲を何度も読み替えると、使わない音のデータが残る | 新しい曲を送ると、前の曲は worklet が手放す。ページを離れる時は音の処理を閉じる(`ToolKit.addCleanup`) |
| スクラッチの音を作る部品が Pro にしかない | Pro の worklet を `common/turntable-worklet.js` に移し、2つのツールで共有する(決定 2026-11-08) |

採らなかった案:

| 案 | 理由 |
| --- | --- |
| 通常版を作り変える | 決定 2026-11-08: 新しいツールにして、通常版と Pro は残す |
| Pro の並びを変える | 同上 |
| サイトの配色(紺紫×ミント、ライト・ダーク)に合わせる | 決定 2026-11-08: 参考どおり暗い地に A ミント・B 琥珀。`ui.md` の「例外: DJ の機械の画面」に書いた |
| B を黄色寄りにする | 同上 |
| ボタンを日本語にする | 決定 2026-11-08: PLAY・CUE など英語のまま。DJ の機械の言葉で短い |
| スクラッチは再生位置を飛ばすだけにする | 2026-11-08 に一度決めたが、利用者の希望で本物の音にした |
| スクラッチの間だけ worklet に切り替え、ほかは `<audio>` で鳴らす | 指を離した時に音が跳ぶことがある。再生をすべて worklet にした(決定 2026-11-08) |
| DJデッキ用に worklet を新しく書く | 似た部品が2つになる(決定 2026-11-08) |

### 2.2 外部仕様

画面の要素(デッキ A・B は同じ):

| 場所 | 要素 | 操作と結果 |
| --- | --- | --- |
| 上 | STOP ALL / RESET MIXER | R-11 |
| デッキの上 | `01 / DECK A`、曲名 | 曲名は読み込むまで `NO TRACK LOADED` |
| デッキ | 盤(ラベルと針の腕) | 再生中は回る(33⅓回転、1周 1.8 秒)。なぞると R-07 |
| 盤の右 | TIME / PITCH / RATE | 今の時間、ピッチ(%)、速さ(×) |
| 盤の下 | 波形、シークバーと `経過 / 長さ` | R-08 |
| | `＋ LOAD TRACK`、ファイル名 | R-01 |
| | PLAY・CUE・RESET・LOOP・HOT CUE | R-02〜R-05。ON の時は枠と文字がそのデッキの色 |
| | PITCH のスライダー | R-06 |
| ミキサー | MASTER OUTPUT、CH A / CH B、HI・MID・LOW、CROSSFADER、FILTER・ECHO、使い方の短い説明 | R-09・R-10 |

- 入力: 端末の音のファイル(`audio/*`)。外へは何も送らない。
- 覚えておく物: 無し。
- 外とのやり取り: ファイルを選ぶ画面だけ。許可は要らない。
- 失敗した時:
  - 音の処理が無い: 画面の上に「このブラウザは音の処理に対応していません」。
  - 読めない曲: そのデッキの曲名の所に「この曲は読み込めませんでした」。波形は空のまま。
- ログ:
  - 結果: `曲を読み込みました(デッキA / 3:25)`(ファイル名は出さない)、`ホットキューを覚えました(デッキA / 1:02)`、`ミキサーを最初の値に戻しました`。
  - ボタンの押下は自動のログ(`data-log` に `デッキA 再生` のような日本語の名前)。スライダーの値の変化はログに出さない(サイトの決まり)。
  - 失敗: `曲を読み込めませんでした(デッキA)`(警告)、音の処理の開始の失敗(エラー)。

### 2.4 処理方式

- ファイル: `dj-decks.html` / `.css` / `.js` と、画面に依らない計算の `dj-decks-core.js`(Node で試験する)。普通のスクリプト。
- 再生: Pro と同じ `common/turntable-worklet.js`(AudioWorklet。出力2つ = デッキ2台)。読み込んだ曲は `decodeAudioData` で展開し、Int16 にして worklet へ所有ごと渡す(記憶領域が半分)。worklet がモーター(立ち上がり・止まり)・指(位置を追うばね)・スリップマット・ピッチ(速さと音の高さ)を受け持つ。
- 画面と worklet の知らせ: 画面から `load` / `motor` / `speed` / `seek` / `touch` を送り、worklet から約 30 回/秒で `state`(位置・速さ・モーター)と、曲の終わりで `ended` が来る。
- 音のつながり: worklet の出力 A・B → チャンネル(音量×クロスフェーダー)→ 混ぜる → LOW → MID → HI → FILTER → MASTER → スピーカー(ECHO は FILTER の後から分けて MASTER へ)。
- クロスフェーダー: 両端で片方が消え、中央で両方が少し下がる曲線(cos / sin)。
- 波形: 読み込んだファイルを `decodeAudioData` で一度だけ解析し、幅に合わせて山の高さ(最大値)の配列を作る。描くのは canvas。今の位置の線は、再生中だけ描き直す(画面の更新に合わせる)。
- スクラッチ: なぞった角度を、何周目も数えて(1 周 = 1.8 秒 = 33⅓回転)worklet へ送る。押さえている間は、指が止まっていても毎フレーム送る(止まったことを伝えるため。`docs/lessons.md` の「音」)。
- 盤の絵: 再生位置から角度を決めて回す(位置 1 秒 = 200 度)。音と絵が必ずそろう。
- 重さ: 解析は読み込みの時の一度だけ。長い曲(10分)でも、山の配列は数千の数で済む。
- 後片付け: ページを離れる時に、音の処理(AudioContext)を閉じる(`ToolKit.addCleanup`)。

## 4. 制限事項と試験

### 4.1 制限事項

- 曲は丸ごと記憶領域に置く(Int16 で、ステレオ 44.1kHz なら 1 分あたり約 10MB)。5 分の曲を2台で約 100MB。
- iPhone の Safari は、`<audio>` を Web Audio につなぐと、画面を消した時に音が止まることがある(要確認)。
- 1曲を丸ごと解析するので、とても長い曲(1時間など)は読み込みに時間がかかり、記憶領域も使う。

設計と違った事:

### スクラッチ / 2026-11-08
